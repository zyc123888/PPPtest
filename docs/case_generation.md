# OmniTest 用例生成

> 状态：已实现，持续维护  
> 功能入口：`/case/generator`  
> 规则方案：`claw_5skill_final`  
> 最后更新：2026-07-20

## 1. 功能定位

“用例生成”用于把 Markdown 需求、文本文件或需求链接转换为可执行测试用例初稿，并导出 XMind。它是当前稳定的原始生成链路，适合：

- 中短篇需求文档的首次用例设计；
- 需要快速获得功能点、测试用例和 XMind 初稿；
- 不需要逐个 source 追溯、分片重跑和强交付门禁的任务；
- 与历史任务保持一致的生成与展示体验。

该功能由一个 Celery 后台任务统一编排多个 Skill 阶段。不同阶段使用不同职责的提示词和结构约束，但不是多个独立 Agent 自主协作。

## 2. 用户输入

| 输入项 | 必填 | 说明 |
|---|---:|---|
| 所属项目 | 是 | 决定任务归属的项目和工作空间 |
| 任务名称 | 是 | 用于最近任务列表和产物命名 |
| 模型配置 | 是 | 使用工作空间已保存配置，或填写 API Key、模型和兼容 Base URL |
| 需求来源 | 是 | 支持粘贴文本、上传文档、需求链接 |
| 需求正文 | 是 | 粘贴或上传时至少 10 个字符 |
| 导出 XMind | 默认开启 | 当前页面固定开启 |

上传文档当前支持 `.md`、`.markdown` 和 `.txt`。文件先由浏览器读取为文本，再随任务提交，不直接作为原始文件上传。

## 3. 执行流程

后端先执行一次确定性任务编排，页面主要展示以下 6 个业务节点：

| 页面节点 | 后端阶段 | 具体工作 | 主要结果 |
|---|---|---|---|
| 收集 | `collect` | 解析需求正文、章节和图片链接，下载可访问图片 | 章节统计、图片下载结果 |
| 识图 | `image_analysis` | 优先识别需求中的图片；失败图片记录为待确认，不伪造识图结果 | 图片语义、识图降级说明 |
| 分析 | `requirement` | 建立证据追踪，提取功能点和待确认项 | `evidence_trace.json`、`function_points.json` |
| 设计 | `testcase` | 按功能点分批调用用例设计 Skill，生成步骤、数据和预期 | `testcase_package.json` |
| 评审 | `review` | 检查功能点覆盖、可执行性、重复、弱预期和风险 | `review_report.json` |
| 导出 | `export` | 确定性生成 XMindMark，转换 XMind，并校验 XMind 中用例节点数 | `.xmindmark`、`.xmind` |

后端内部的 `orchestrate` 阶段负责生成执行计划，目前不作为页面独立进度节点展示。

## 4. 关键处理规则

### 4.1 需求与图片

- Markdown 标题和正文用于章节拆解。
- 图片链接会下载到任务独立目录后再进行识别。
- 下载失败或模型无法识图时，系统记录失败原因并转为待确认信息。
- 需求原文、图片语义和功能点之间保留证据引用。

### 4.2 功能点与用例

- 功能点是需求分析结果，不等同于最终用例数。
- 用例按功能点分批生成，最终进行全局去重和重新编号。
- 最终用例编号采用 `TC-功能点序号-用例序号` 的形式。
- 用例数量以 `testcase_package.testcases` 的实际条目数为准。

### 4.3 质量审查

质量审查只生成结论和报告，不再自动进入多轮返工循环：

- `pass`：任务状态为 `SUCCESS`；
- `conditional_pass`：任务状态为 `CONDITIONAL`，保留改进建议；
- `fail`：仍可生成供人工检查的草稿 XMind，但任务不得表示为可信成功，状态为 `CONDITIONAL`。

因此，“已导出 XMind”不一定代表质量审查完全通过，用户还需要查看任务状态和审查结论。

### 4.4 XMind 一致性

XMind 由后端根据最终 `TestcasePackage` 确定性展开，不由模型直接编写归档。导出后系统会解析 XMind 文件，并校验其中的 `TC-` 用例节点数与用例包一致；不一致时任务失败。

## 5. 页面功能

### 5.1 最近任务

- 显示任务名称、编号、状态和简化摘要；
- 支持按状态筛选；
- 进行中的任务固定显示在列表顶部；
- 同一用户已有进行中任务时，不允许重复提交新任务。

### 5.2 结果详情

- 显示任务状态、摘要、来源文档和错误信息；
- 显示阶段进度、阶段耗时和阶段摘要；
- 显示最终 XMind 下载入口；
- 可查看导出日志和模型调用轨迹等可见产物；
- 支持刷新详情、重跑和停止任务。

### 5.3 重跑与停止

- 重跑使用原任务输入，并读取当前最新的工作空间模型配置；
- 重跑会创建新的 attempt，旧 attempt 保留用于追踪；
- 停止会撤销当前任务并将状态更新为 `CANCELLED`；
- 已被新 attempt 替代的旧任务结果不会覆盖最新结果。

## 6. 任务状态

| 状态 | 含义 |
|---|---|
| `PENDING` | 已提交，等待 Worker 执行 |
| `RUNNING` | 正在执行 |
| `SUCCESS` | 生成、审查和导出均完成 |
| `CONDITIONAL` | 已生成结果，但存在需人工复核的问题 |
| `FAILED` | 模型调用、结构校验或导出失败 |
| `CANCELLED` | 用户已停止任务 |

## 7. 产物

| 产物 | 用途 | 页面默认展示 |
|---|---|---:|
| `evidence_trace.json` | 需求与图片证据追踪 | 否 |
| `function_points.json` | 功能点和待确认项 | 否 |
| `testcase_package.json` | 最终结构化用例包 | 否 |
| `review_report.json` | 审查结论和问题清单 | 否（后台保存） |
| `delivery_summary.md` | 交付摘要 | 否 |
| `.xmindmark` | XMind 的可审计中间格式 | 作为任务产物保存 |
| `.xmind` | 最终可下载思维导图 | 是 |
| `xmind_export_log.json` | 导出失败原因 | 导出失败时显示 |
| `model_call_trace` | 模型调用轨迹 | 是 |

页面是否展示某个中间产物与后台是否保存该产物是两个概念；未显示的产物仍可用于审计和问题定位。

## 8. 异常处理

| 问题 | 系统行为 | 建议操作 |
|---|---|---|
| 缺少 API Key | 任务失败，不使用占位结果 | 保存有效模型配置后重跑 |
| 模型超时或 5xx | 当前阶段失败并保留错误 | 等待模型恢复后重跑 |
| JSON 输出截断 | 结构解析失败 | 重跑；长文档建议改用“用例生成2”可信模式 |
| 图片下载或识别失败 | 记录失败并进入待确认 | 检查图片可访问性，必要时补充文字说明 |
| 质量审查未通过 | 条件导出草稿，不标记完全成功 | 查看审查报告并人工修订 |
| XMind 数量不一致 | 阻止任务成功 | 查看导出日志后重跑 |
| 长时间无心跳 | Watchdog 标记异常 | 确认 Worker 状态后重跑 |

## 9. 与“用例生成2”的边界

“用例生成”强调稳定、直接和兼容；“用例生成2”增加：

- 轻量模式与可信模式；
- SourceManifest、证据门禁和范围索引；
- source/function point/testcase 的可追溯回执；
- 按 source 分片生成与失败分片重跑；
- 确定性门禁、模型语义审查和最终交付门禁；
- 更完整的运行指标和可信指标。

原版与 V2 使用独立任务表和产物，不应互相覆盖。

## 10. 当前限制

- 页面上传只支持 Markdown 和纯文本，不直接解析 Word、PDF 或 XMind。
- 对超长手册类文档的首次生成耗时可能较长，且单次模型输出更容易截断。
- 审查为单次定稿，不自动执行多轮修复。
- 原版不提供 source 级预算、消费回执和分片重跑。
- 模型服务稳定性直接影响任务时长和成功率。

## 11. 维护规则

以后修改“用例生成”时，必须同步更新本文档：

1. 输入字段、页面交互或状态发生变化；
2. 阶段顺序、Skill、提示词职责或校验规则发生变化；
3. 新增、删除或重命名产物；
4. 修改任务重跑、停止、超时或 Watchdog 行为；
5. 修改 XMind 结构、统计口径或审查结论语义。

规划中的功能只能写入“当前限制”或单独计划文档，不得标记为已实现。
